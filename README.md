# Candlestick Pattern Recognition System

Turn price data into chart images, train a YOLO detector to localise candlestick
patterns in them, then feed the detector's **own predictions** into a next-day
direction classifier to test whether "a pattern was detected" actually improves
prediction over a price-feature baseline.

The result is reported as found. A null result is the expected outcome and is
written up as plainly as a positive one would be.

## Problem statement

Candlestick patterns are among the most widely taught ideas in technical
analysis, and among the least convincingly evidenced. This project separates the
two questions that usually get conflated:

1. **Can a vision model find these patterns on a chart?** A detection problem
   with a measurable answer (per-class precision, recall, mAP).
2. **Does finding one tell you anything about tomorrow?** A prediction problem,
   answered out-of-sample with a significance test rather than an anecdote.

Treating them separately matters, because a detector can be excellent at
question 1 while the answer to question 2 is still "no". Most write-ups stop
after question 1 and imply the second.

### What this project is not

It is not a trading system, and nothing here is investment advice. The strategy
returns shown in the results exist to put the classifier's edge on a familiar
scale, not to propose trading it.

## The labels are rule-based, and that is a real limitation

Every bounding box in the training data was generated by **TA-Lib's `CDLxxx`
functions**. No chart was annotated by a human.

This was a deliberate trade — full automation and perfect reproducibility, in
exchange for labels that are a published heuristic rather than ground truth. The
consequences are worth stating directly:

- The detector learns to imitate TA-Lib. Where TA-Lib and an experienced trader
  would disagree about the same candles, this model follows TA-Lib.
- Detection metrics measure **agreement with a rule**, not correctness.
- The downstream study is therefore a test of whether *TA-Lib's notion of a
  pattern, seen through a detector's eyes*, carries information — not a verdict
  on candlestick analysis as a discipline.

The demo shows the detector's boxes and TA-Lib's own output side by side, so the
gap between the rule and the model that learned it is visible rather than
asserted.

## Datasets

| | |
|---|---|
| Source | Yahoo Finance daily OHLC via `yfinance`, split/dividend adjusted |
| Signal instrument | **SPY** (1993-01-29 onward, 8,465 bars) |
| Detector training extras | 10 large caps (AAPL, MSFT, JPM, XOM, JNJ, KO, GE, WMT, PG, T) |
| Chart format | 640x640 PNG, 20 candles, no axes, no gridlines, no volume panel |
| Classes | 8: Hammer, Shooting Star, Bullish/Bearish Engulfing, Morning/Evening Star, Doji, Harami |
| Published at | [`rohanjain2312/candlestick-pattern-recognition-system-data`](https://huggingface.co/datasets/rohanjain2312/candlestick-pattern-recognition-system-data) |

### Why extra tickers

On SPY alone the training split contains only **27 Morning Stars and 29 Evening
Stars** — below the threshold at which a class is worth training. Rather than
drop two of the eight classes, the auxiliary tickers supply enough examples of
the rare three-candle formations. They appear in the **training split only**:
validation and test are SPY-only, so held-out metrics describe the instrument
the downstream study actually uses.

### Splits are chronological, with an embargo

| split | period | images |
|---|---|---:|
| train | through 2014-12-31 | 12,151 |
| val | 2015-02-02 to 2018-12-31 | 986 |
| test | 2019-01-31 onward | 1,917 |

Splitting purely on end-date is **not sufficient** here. Consecutive windows
overlap in 19 of their 20 candles, so a window ending one day after a boundary
is nearly the same image as one ending the day before it. The first 20 windows
of each split are therefore discarded, which makes val and test share no candle
with any training image. Nothing anywhere in this project is split randomly.

## Architecture

```
yfinance ──> data/raw/*.parquet
                │
                ├──> TA-Lib CDLxxx ──> pattern hits (bar, class, span)
                │                              │
                └──> mplfinance 20-candle ─────┤
                     window render             │
                            │                  │
                            ▼                  ▼
                     640x640 PNG   +   YOLO boxes from the chart's
                                       own matplotlib transform
                            │
                            ▼
                     YOLO11n fine-tune  (Colab T4, checkpointing to the Hub)
                            │
              ┌─────────────┴──────────────┐
              ▼                            ▼
     per-class test metrics        detections on every SPY day
                                           │
                        price features ────┤
                                           ▼
                            logistic regression, walk-forward
                          baseline  vs  baseline + detections
```

### Design decisions worth knowing about

**Boxes come from matplotlib, not arithmetic.** Each chart is rendered first,
then the axes are asked for their own data-to-pixel transform. Box geometry is
exact by construction and survives any change to chart style or padding.

**Every pattern in the frame is labelled, not just the latest one.** If only the
right-most candle were boxed, the same visual candle would be a labelled object
in one image and unlabelled background in the next — contradictory supervision
that quietly degrades a detector. So all patterns fully inside the window are
boxed, and the downstream feature reads only the detection covering the
right-most candle.

**Causality is enforced and tested.** A chart for date *t* contains bars up to
*t* and nothing after; the target is the move from *t* to *t+1*. TA-Lib is run
over the whole series and its hits are then *sliced* into windows, never
recomputed on a fragment. `tests/test_labeling.py::test_labels_are_causal` and
`tests/test_features.py::test_features_are_causal` assert this rather than
assume it.

**The downstream features are the detector's predictions, not the labels.**
Feeding the TA-Lib labels back in would only prove that TA-Lib is
self-consistent. Using the detector's output — errors included — measures what a
model that had to read the picture can actually extract.

**An asymmetry, stated rather than buried.** The downstream classifier trains on
dates going back to 1993, and the detector saw charts from that early period
during its own training. The pattern features it learns from are therefore
sharper than the ones it meets in the evaluation window, where the detector is
genuinely out of sample. This shift works *against* the pattern variant, so it
cannot manufacture a positive result — but it is a real property of the setup
and belongs in the open.

**No GAN, and no horizontal flips.** Class imbalance is handled with
augmentation instead. Flip and rotation are explicitly disabled: mirroring a
candlestick chart runs time backwards and turns a Bullish Engulfing into
something that never occurs, which would corrupt the labels rather than augment
them.

## Results

_Generated by `python -m src.evaluation.report --inject`; every number below is read from `results/*.json`._

### Downstream signal: does a detected pattern predict tomorrow?

**Detected patterns did not improve next-day direction prediction.** Accuracy moved by +0.0036, with a 95% bootstrap interval of -0.0041 to +0.0114 that contains zero, and McNemar's test gives p = 0.443. On this evidence, knowing that the detector saw a candlestick pattern at the close adds nothing to a plain price-feature baseline.

Out-of-sample 2019-01-01 to 2026-09-15 (1936 trading days on SPY). expanding-window walk-forward, annual refit, no shuffling.

| metric | baseline | + detected patterns | difference |
|---|---:|---:|---:|
| Accuracy | 0.5527 | 0.5563 | 0.0036 |
| ROC AUC | 0.4964 | 0.4974 | 0.0010 |
| Brier score (lower is better) | 0.2481 | 0.2484 | 0.0003 |
| F1 | 0.6976 | 0.6970 | -0.0006 |
| Share of days predicted "up" | 0.926 | 0.911 | -0.015 |
| Strategy return, net of costs | 2.7513 | 2.8575 | 0.1062 |
| Sharpe, net | 1.074 | 1.095 | 0.021 |
| Majority-class rate | 0.5537 | | |
| Buy and hold, same period | 2.3692 | | |
| Buy and hold Sharpe | 0.917 | | |

The majority-class rate is the accuracy of always predicting "up". On a long-drifting index it sits well above 50%, so a model that merely matches it has learned nothing. Here **neither variant beats it**: baseline is -0.0010 against it and +patterns +0.0026.

> **Do not read the return rows as an edge.** Both variants have a ROC AUC of about 0.497 — no better than chance at ranking one day above another — and both predict "up" on at least 91% of days. The strategy is therefore buy-and-hold with a handful of days sat out, and its Sharpe of 1.095 (buy and hold over the same days: 0.917) reflects which days those happened to be, not an ability to pick them. Accuracy that does not clear the majority-class rate of 0.5537 cannot coexist with a genuine trading edge.

The detector fired on the most recent candle on 31.9% of days (mean 0.36 detections per chart), so the pattern columns were far from constant — a null result here is not an artefact of the features always being zero.

### Detection, held-out test split

1917 SPY charts, chronologically after every training chart, with an embargo gap.

| class | test instances | precision | recall | mAP@50 | mAP@50-95 |
|---|---:|---:|---:|---:|---:|
| Hammer | 557 | 0.665 | 0.720 | 0.757 | 0.756 |
| ShootingStar | 570 | 0.801 | 0.798 | 0.893 | 0.893 |
| BullishEngulfing | 1178 | 0.999 | 0.983 | 0.995 | 0.995 |
| BearishEngulfing | 1368 | 0.908 | 0.997 | 0.976 | 0.976 |
| MorningStar | 198 | 0.602 | 0.773 | 0.772 | 0.771 |
| EveningStar | 180 | 0.773 | 0.550 | 0.669 | 0.667 |
| Doji | 5261 | 0.893 | 0.948 | 0.975 | 0.975 |
| Harami | 2350 | 0.824 | 0.946 | 0.944 | 0.943 |
| **aggregate** | | **0.808** | **0.839** | **0.872** | **0.872** |

Per class rather than one number: Doji outnumbers Evening Star by more than an order of magnitude, so an averaged mAP is driven by the rarest class and hides how the detector does on the common ones.

**Which patterns the detector finds easy, and why.** The strongest classes are BullishEngulfing, BearishEngulfing and Doji; the weakest are MorningStar, Hammer and EveningStar. The pattern is not random: classes defined by a *relationship between whole candle bodies* — is this body larger than the previous one, is it contained within it — are close to solved, because that is a crisp geometric comparison at chart scale. The weaker classes are the ones defined by a *proportion inside a single candle*, such as a lower wick at least twice the body. At 640x640 with 20 candles, a body is only a few pixels tall, so the very measurement the rule depends on is the one the image barely resolves. On EveningStar the model errs by **missing** rather than mislabelling (recall below precision): it declines to call the pattern rather than calling the wrong one, which for a downstream signal is the safer failure — it removes observations instead of corrupting them. On MorningStar and Hammer the balance runs the other way (precision below recall): the model finds most of the real instances but also calls some that the rule does not, so those columns carry false positives as well as noise.

### Caveats that apply to all of the above

- Labels are TA-Lib `CDLxxx` rules, **not** human annotation. The detector imitates a heuristic; where the rule and a trader disagree, the model follows the rule.
- Every split is chronological with an embargo gap. Nothing is shuffled.
- The downstream study uses the detector's **own predictions**, not the labels it was trained on, so it measures what a model reading the picture can extract — mistakes included.
- Returns shown are an illustration of the classifier's edge, net of a modelled spread only. They ignore slippage, financing and taxes, and are not a trading recommendation.

## Reproducing this

```bash
git clone https://github.com/rohanjain2312/candlestick-pattern-recognition-system
cd candlestick-pattern-recognition-system
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # fill in GITHUB_TOKEN and HF_TOKEN
```

```bash
python -m src.labeling.build_dataset          # fetch, render, label  (~10 min, CPU)
python -m src.detection.push_to_hub all       # create HF repos, upload the dataset
# -> run notebooks/03_yolo_finetune_colab.ipynb on a Colab T4  (the only GPU step)
python -m src.evaluation.detection_metrics    # per-class held-out metrics
python -m src.downstream_signal.run_study     # the predictive-signal comparison
python -m src.evaluation.report --inject      # write results into this README
pytest -q
```

TA-Lib needs no system library: the `TA-Lib` wheel is self-contained, so no
Homebrew and no `sudo` are required on macOS.
